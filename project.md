## 3. Pages & Routes

There is **no router and no multi-page navigation**. `src/App.jsx`:

```jsx
<Hero />
<Projects />
<Skills />
<Contact />
<Footer />
```

All rendered stacked vertically in `#root` (flex column, `gap: 60px` mobile → `100px` ≥800px → `200px` ≥1400px).

| "Page" (section) | Anchor id | Contents | Navigation to/from |
|---|---|---|---|
| Hero | `id="hero"` (`Hero.jsx`) | Photo, theme toggle, H1 name, H2 role, 3 social icons, 1-line tagline, Resume download button | No nav links point to it; no links out except external socials + CV download. |
| Projects | no `id` (`Projects.jsx` `<section>` has no id) | H1 `projects`, 4 image cards | Cards all `href="_"` (placeholder, reloads/navigates to `_` path — effectively dead links). No detail pages. |
| Skills | `id="skills"` | H1 `skills`, 10 skill pills in 2 rows separated by `<hr/>` | No nav; static. |
| Contact | `id="contact"` | H1 `Contact`, form (Name/Email/message + Submit), loader backdrop, success modal | Submit triggers EmailJS; success shows PopUp modal; no redirect. |
| Footer | `id="footer"` | Copyright paragraph | Static. |
| PopUp modal | no route; conditionally rendered in `Form.jsx` when `done===true`; also commented out in `main.jsx` (`{/* <PopUp /> */}` without required prop) | Overlay + card + check icon + Thanks text + confirm button | Opened on EmailJS success; closed via `handleConfirm` → `setDone(false)`. |

Browser scrolling is the only "navigation". No navbar, no footer links, no scroll-to-top, no active-section highlighting, no 404.

### 5.2 Typography
- **Loaded from:** Google Fonts via `<link>` in `index.html`: `Roboto Mono:ital,wght@0,100..700;1,100..700` + `Rubik:ital,wght@0,300..900;1,300..900`, with `preconnect` to `fonts.googleapis.com` / `fonts.gstatic.com crossorigin`. No local `@font-face`, no `font-display` override beyond Google default.
- **Applied in `App.css`:**
  - `h1 { font-family: "Rubik", sans-serif; font-size: 32px; }` → `40px` @≥800px → `48px` @≥1400px.
  - `h2 h3 p` selector (bug: this means "h3 inside h2 inside p" — effectively matches nothing; intent was `h2, h3, p`) declares `font-family: "Roboto Mono", monospace; font-size: 20px;` — so in practice h2/h3 fall back to browser default font, NOT Roboto Mono, except where inherited elsewhere. `h2,h3 { font-size: 24px; }` only inside @≥800px media query (base h2/h3 size otherwise browser default ~24px/18.7px).
  - `p { font-size: 16px; font-weight: 300; }` → `20px` @≥800px. Footer `p` overridden to `16px` in its module (stays 16px at all breakpoints).
  - `.sectionTitle { margin-bottom: 30px; }` → `60px` @≥800px → `75px` @≥1400px. Only `Contact` actually uses `styles.sectionTitle` (+ inline `padding:20px`); Skills uses inline `style={{padding:"20px"}}` instead.
- **Component-level sizes:**
  - Hero Resume `button`: `20px bold`; Contact submit: `20px bold`; PopUp `h3 24px bold`, confirm btn `20px bold`; skill `p` `20px` only @≥800px (base inherits 16px light-weight).
  - Form fields @≥800px: `font-size: 20px`.
- **Line-height / letter-spacing:** never set (browser defaults).
- **Text transform:** none (headings render as written: `projects` and `skills` lowercase in JSX, `Contact` capitalized).

### 5.3 Spacing / layout system
- No spacing scale/token, no grid. All flexbox column/row, centered text.
- Global: `body { display:flex; justify-content:center; margin: 0 auto 60px; }`, `#root { display:flex; flex-direction:column; gap:60px; }` → `gap:100px` @≥800px → `gap:200px` @≥1400px. `:root { text-align:center; box-sizing:border-box; }`.
- Hero `.container`: `flex column, justify-center, gap:20px, text-center, height:100dvh, min-height:500px` → @≥800px `flex-direction:row-reverse, align-center, justify-space-evenly`. `.info`: `flex column gap:20px`. Social `span`: `flex gap:25px justify-center`.
- Projects `.projectsContainer`: `flex column justify-center gap:20px margin-top:1rem` → @≥800px `row wrap justify-space-evenly gap:40px padding:0 30px`.
- Skills `.skillList`: `flex justify-center align-self:center flex-wrap row-gap:40px gap:20px max-width:26ch` → @≥800px `max-width:fit-content gap:30px`. Divider `hr`: `width:100px height:1px margin:30px auto` → `width:300px margin:50px auto` @≥800px.

- **Breakpoints (non-standard syntax `@media (width >= ...)` — valid in modern browsers, equivalent to `min-width`):** `800px` (mobile→desktop) and `1400px` (large desktop). No tablet-specific or max-width rules. One broken query `@media (width >= 1400x)` in `ContactStyles.module.css:70`.

### 5.7 Dark / light mode
- Supported via `ThemeContext` + `body[data-theme]` + CSS vars. Toggle is the sun/moon image in Hero (`onClick={toggleTheme}`), persisted in `localStorage` key `theme`. Default `light` (no `prefers-color-scheme` detection).
- Theme-aware: page bg, all heading/body text, button bg/text (inverted: `#213547`/`#fff` ↔ `white`/`#222`), form text/placeholder, footer text, all social/checkmark/toggle icons (light/dark pairs).
- **Not theme-aware (stay fixed):** project card link color `#222`, project images, PopUp modal (always white bg + `#212121` text), `#73b4ed` hover, form field borders `#888`, loader color `#fff`.

### 5.8 Inconsistencies noticed (factual)
1. `---btn-color` triple-dash typo in `App.css` (both themes) — dead var; intended blue `#0987f2` never used; actual button color is `--mybtn-color: #213547`.
2. `Hero.jsx` uses `styles.discription` (typo) but CSS defines `.description` — so `max-width:24ch` never applies; class resolves to `undefined`.
3. `h2 h3 p` selector in `App.css:43` (missing commas) matches nothing; Roboto Mono therefore not reliably applied to h2/h3/p.
4. `input:not([type="sumbit"])` typo (`sumbit`) in `ContactStyles` (lines 13, 59, 72) — still matches text/email inputs by accident (since their type ≠ "sumbit"), but is fragile/confusing.
5. `@media (width >= 1400x)` missing `p` (`ContactStyles:70`) — entire 800px-field-width rule dead.
6. Checkmark naming inverted: `checkmark-light.svg` is dark (`#222`) and used in light theme; `checkmark-dark.svg` is white and used in dark theme. Same pattern for socials (light file = dark glyph). Works visually but confusing.
7. Project link color `#222` fixed while bg goes dark → poor dark-mode contrast; `--project-card-bg` var defined but unused.
8. Button shadows differ per component (`0 4px 4px` vs `2px 10px 5px` vs `0 9px 4px`) — no shared token.
9. Two Resume PDFs exist but only `M2-CV.pdf` is linked; `Fettah_Safi_CV_ATS_v3.pdf` orphaned. `watch.png` vs `Watchs.png` duplicate-ish; only `Watchs.png` used.

11. `PropTypes.node` misused for string URLs (`Skill` props) and function (`PopUp handleConfirm`); should be `string` / `func`.
12. `ThemeContext toggleTheme` uses `useCallback(..., [theme])` + assignment-in-ternary `theme = "dark"` side-effect style; works but non-idiomatic and re-created each theme change.
13. `index.css` empty yet imported; `.toggle-btn` + `.hover` (cursor only) classes partially dead; `PopUp` commented out in `main.jsx` without required prop.

## 8. Current Limitations / Rough Edges

1. **No routing / nav:** single scroll, no navbar, Projects section has no `id` so can't even be anchor-linked. All project links are `href="_"` placeholders.
2. **SEO:** `<title>pers-Portfolio</title>` (typo), no `<meta name="description">`, no Open Graph/Twitter cards, no `theme-color`, no sitemap/robots inspected. Single `h1` per section (multiple h1s total) with lowercase headings.
3. **Accessibility:** icon-only links with weak alts (`Linkedin`, `Twitter`, `Github`, `color mode icon`, `clock Pic` mismatches, empty `alt=""` on checkmarks); hidden form `<label>`s (two say `Name` for email/message); no `aria-label` on theme toggle (it's an `<img onClick>`, not a `<button>`, so not keyboard-focusable); no focus-visible styles; color contrast fails for `#222` links on `#232323` dark bg; `lang="en"` is the only a11y win.
4. **Responsiveness gaps:** only 800px/1400px breakpoints; form jumps 250px→600px with no intermediate; 1400px field rule broken (`1400x`); `Library.png` is 9.4 MB with no lazy-loading/`srcset`/`width/height` attrs (layout shift + slow load); project images fixed `250×250` may distort non-square sources.
5. **Outdated / sloppy patterns:** triple-emailjs deps (`@emailjs/browser` + `emailjs` + `emailjs-com`); `@mui/icons-material` installed but unused; `PropTypes.node` misuse; manual `skillsArr[0..9]` instead of `.map` (dead commented code); `useCallback` with `[theme]` dep + assignment ternary; `body[data-theme]` set via effect (flash of default theme on load); CSS nesting (`.container { img {...} }`) relies on modern browsers / Vite LightningCSS — fine now but no fallback; non-standard `@media (width >= ...)` syntax.
6. **Missing states / error handling:** no form validation beyond `required` + `type="email"`; `sendEmail` failure does `throw new Error(err)` inside promise rejection (uncaught, no user-facing error UI, loader just closes); fields cleared before success confirmed; no retry; no `disabled` state on submit while `open`; PopUp `confirm` is the only feedback.
7. **Content/UX unfinished:** `PopUp` commented out in `main.jsx`; `index.css` empty; `public/vite.svg` + 5 unused PNGs + 1 unused PDF + `linkedin.png` + `watch.png` bloat the bundle/assets; footer year hardcoded `2024`; `console.log("SUCCESS!", ...)` left in `Form.jsx`; `alt="clock Pic"` / `alt="online library"` mismatches; `href="_"` cards; no loading="lazy", no 404, no scroll restoration concerns (single page).
8. **Theming bugs:** `---btn-color` dead; `--project-card-bg` dead; modal always white (acceptable) but toggle border uses theme var so nearly invisible in one mode; checkmark/social naming inverted (maintenance hazard).

## 9. Data Flow

- **No CMS, JSON, API (except EmailJS send), store, or router.** All content is **hardcoded in JSX**:
  - Hero copy/links/CV import in `Hero.jsx` lines 36–60.
  - Project titles/descriptions/images in `ProjectCard.jsx` lines 6–26 + image imports in `Projects.jsx` lines 2–5.
  - Skills list `skillsArr` array literal in `Skills.jsx` lines 6–17.
  - Footer text in `Footer.jsx` line 6.
  - Modal text in `PopUp.jsx` lines 9–11.
- **Theme state:** `ThemeContext.jsx` — `useState(localStorage.theme || "light")` → `toggleTheme()` → `useEffect` writes `document.body[data-theme]` + `localStorage`. Consumed via `useThemeContext()` in `Hero` (toggle + icon swap) and `Skills` (checkmark swap).
- **Contact flow:** `Form.jsx` local `useState` for `name/email/message/open/done` → `handleChange` by `e.target.name` → `handleSubmit` prevents default, sets `open=true`, builds `{ from_name, from_email, message }`, calls `sendEmail()` (`email.js` reads `VITE_EMAILJS_*` from `.env`) → on resolve `open=false, done=true` (shows `PopUp`); on reject `open=false` + throws. Fields reset synchronously right after calling `sendEmail` (not after success).
- **How to update content (as-built):** edit the JSX literals / `skillsArr` / image imports directly; replace `src/assets/M2-CV.pdf` or change the import in `Hero.jsx` for a new resume; rotate EmailJS keys in `.env` (`VITE_EMAILJS_PUBLIC_KEY/SERVICE_ID/TEMPLATE_ID`); add a project by adding another `<a>` block in `ProjectCard.jsx` + importing the image in `Projects.jsx` and extending the `pics` prop + PropTypes. No build-time data fetching, no env-driven copy, no i18n.
